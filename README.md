# Ol Saathi (ओल साथी)

**SIH26042 · Government of Jharkhand · Team INNOV8, JAIN Deemed-to-be University**

Ol Saathi is an offline-first Android app that lets a Hindi-speaking primary teacher deliver a lesson in Santali (Ol Chiki script) without knowing the language. The teacher speaks Hindi; the app translates, displays, and speaks Santali. Fully offline, on a low-cost tablet. No internet required.

---

## The problem

Over 5,000 tribal-area primary schools in Jharkhand need foundational literacy and numeracy (FLN) teaching in Santali, Ho, and Mundari. Teachers are Hindi-medium trained and cannot speak these languages. PALASH (Programme for Adventure Learning in Academic Schools of Habitat) works well in settings where bilingual resources exist, but it cannot scale to thousands of classrooms where no bilingual teacher or bilingual material is available. There is no digital Ol Chiki keyboard, no Santali TTS engine on Android, and no internet in most of these schools.

Ol Saathi bridges this gap by shipping pre-translated content offline.

## The four graded requirements

| # | Requirement | Status |
|---|-------------|--------|
| 1 | Hindi to tribal-language translation, minimum one language | **Done** — Santali (Ol Chiki) via pre-translated pack from Bhashini |
| 2 | Real-time voice-to-voice translation, under 3 seconds | **Code done, instrumented** — latency measured at lookup time; not yet measured on hardware |
| 3 | Auto-generated bilingual worksheet | **Done** — A4 PDF with Hindi + Ol Chiki, NIPUN outcome codes, share/print |
| 4 | Full offline operation on Android 9+ tablet, 2 GB RAM | **Code done** — minSdk 28, zero network calls; not yet run on a physical tablet |

### What is not done

- **No Santali system voice on Android.** Android has no Santali TTS engine. Audio comes from pre-rendered WAV files produced by Bhashini's Santali TTS, shipped in the content pack. That account is still pending, so the pack currently has zero audio files. The play button stays disabled with a clear message.
- **Latency not measured on hardware.** The code instruments every lookup and round trip. The sub-3-second target is expected (lookup is microseconds), but we have not yet run it on a physical tablet.
- **Pack is pending Bhashini credentials.** The content pack currently holds sample data. The real pack is being generated by a separate agent with Bhashini's IndicTrans2 service.

## Architecture

**No machine learning runs at runtime.** Zero. All Santali content is translated once, ahead of time, by Bhashini (the Government of India language platform) and stored as JSON plus pre-rendered WAV files inside the APK. At runtime the app does a hash lookup.

This is not a shortcut. It is the correct design for this problem, and it is what the problem statement's own phrase *"after initial content synchronisation"* permits. Four things follow:

1. **Offline is trivial.** There is nothing left to call.
2. **Sub-3-second latency becomes a measurement, not a hope.** A hash lookup is microseconds.
3. **The demo cannot fail on stage.** No network, no model loading, no variance.
4. **The authority on Santali is Bhashini, not us.** Every translation entry records the Bhashini service ID. If a judge disputes a translation, the answer is "that is MeitY's own platform."

## The provenance rule

Every piece of Santali text the app displays carries a `Provenance` label shown on screen:

| Label | Meaning |
|-------|---------|
| **VERIFIED** | Real translation from Bhashini's IndicTrans2 |
| **SAMPLE** | Placeholder data, not Bhashini output — stamped in red across worksheets |
| **TRANSLITERATED** | Hindi respelled in Ol Chiki — not a translation |
| **UNAVAILABLE** | No match in the pack. Empty string. No fallback. |

The app never invents output. A lookup miss returns an empty string. There is no fallback phrase, no "close enough" match, no generic Santali sentence for unrecognised input. This rule exists because a previous version shipped exactly that, and a Santali speaker would have noticed immediately.

## Build and run

### Prerequisites

- **JDK 17** (required by Gradle 8.2). JDK 21+ will fail.
- Android SDK with API 35 platform

### Commands

```bash
# Debug build
JAVA_HOME="/path/to/jdk-17" ./gradlew :app:assembleDebug

# Unit tests (17 tests over the shipped content pack)
JAVA_HOME="/path/to/jdk-17" ./gradlew :app:testDebugUnitTest

# Release build (signed with app/release-key.jks)
JAVA_HOME="/path/to/jdk-17" ./gradlew :app:assembleRelease
```

### Output

- Debug APK: `app/build/outputs/apk/debug/app-debug.apk` (~30 MB)
- Release APK: `app/build/outputs/apk/release/app-release.apk` (~22 MB)

### Install on tablet

See [DEMO.md](DEMO.md) for full install steps (USB + sideload).

## Project structure

```
app/src/main/java/app/olsaathi/
├── OlSaathiApplication.kt        App startup, pack loading, latency tracking
├── content/
│   ├── Translation.kt            Provenance enum + Translation data class
│   └── VerifiedContentPack.kt    JSON pack loader + lookup engine
├── speech/HindiSpeechInput.kt    Android SpeechRecognizer wrapper (hi-IN, offline)
├── audio/PackAudioPlayer.kt      WAV playback from assets
├── worksheet/WorksheetPdf.kt     A4 bilingual PDF via PdfDocument
├── util/NetworkGuard.kt          Offline enforcement + call counter
└── ui/
    ├── LessonListActivity.kt     Entry point, lesson browser
    ├── ClassroomActivity.kt      The demo screen
    ├── WorksheetActivity.kt      PDF generation + share/print
    └── ProofActivity.kt          Live-proof screen for judges
```

**11 Kotlin files.** Roughly a dozen is right for a project this size.

## What is not built

We deliberately did not build:

- ONNX Runtime, semantic search, OCR, Wi-Fi Direct mesh, thermal printing, a custom Ol Chiki keyboard, telemetry overlays, analytics dashboards, flashcards, Ho/Mundari translation, user accounts, or a backend.

Every one of these was in a previous attempt. None is graded. Together they are why the six that are graded were never finished.
